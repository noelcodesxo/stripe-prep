# Problem 7 — Payment Card Validation

*An original problem in the shape of a common Stripe Luhn/card OA.*

Build shared Luhn and network-check helpers, then extend one `Solution.solve` flow to
accept plain, redacted, and corrupted card requests. Every input line produces one
stable pipe-delimited row:

```text
<source>|<outcome>|<count>|<details>
```

There are three networks:

- `VISA` — 16 digits, starts with `4`;
- `MASTERCARD` — 16 digits, first two digits `51`–`55`;
- `AMEX` — 15 digits, starts with `34` or `37`.

Luhn validation doubles every second digit from the right, subtracts 9 if the doubled
value exceeds 9, sums the digits, and accepts when the sum is divisible by 10.

## Part 1 — Visa checksum

Input is a plain 16-digit Visa number. `outcome` is `VISA` if Luhn passes, otherwise
`INVALID_CHECKSUM`. For plain cards, `count` is `1` only for a valid card and `0`
otherwise; `details` is `-`.

```text
4532015112830366 -> 4532015112830366|VISA|1|-
```

## Part 2 — Multi-network plain cards

Plain card requests may match any network. Check the network before Luhn: `outcome`
is the network when valid, `INVALID_CHECKSUM` when a network matches but Luhn fails,
or `UNKNOWN_NETWORK` when no network matches. Plain-card row fields stay the same.

## Part 3 — Redacted cards

Input may contain 1–5 `*` wildcards. Try every digit substitution. The row's `source`
is the original pattern, `outcome` is `REDACTED`, and `count` is the total number of
distinct valid completions across all networks. `details` lists each network with at
least one completion as `NETWORK=count`, comma-separated and sorted alphabetically.
Use `-` if there are no valid completions.

```text
453201511283036* -> 453201511283036*|REDACTED|1|VISA=1
```

Plain-card requests continue to use their Part 1/2 rows in the same input.

## Part 4 — Corrupted cards

Input may end with `?`, a marker that is removed before reconstructing the card.
Exactly one operation must be applied to the visible digits: change one digit to a
different digit, or swap two adjacent digits that are different. An unchanged card
and swapping identical adjacent digits do not count as an operation. Generate every
distinct valid original. The row's
`source` is the original `?` pattern, `outcome` is `CORRUPTED`, and `count` is the
number of distinct valid originals. `details` lists them as `digits:NETWORK`,
semicolon-separated and sorted numerically ascending. Use `-` when there are none.
Plain and redacted rows retain their earlier formats.

```text
340000000000009? -> 340000000000009?|CORRUPTED|1|340000000000090:AMEX
```

## Traps to watch

- Sort network counts alphabetically and corrupted candidates numerically.
- Deduplicate candidates that can be generated by both a digit change and a swap.
- Check length and prefix before running Luhn on a candidate.
